# 주간보고 작성 스킬

## 절차

1. **직전 보고 확인**: `docs/weekly-report-*.md` 중 최신 파일을 읽어 형식과 "다음 주 계획"을 파악한다 (이번 주 진척과 대조해야 함).
2. **이번 주 데이터 수집** (추측 금지, git 기반):
   - `git log --since="직전 보고 날짜" --no-merges --format="%h %ad %s" --date=format:"%m-%d"` — 커밋 목록
   - `git diff --shortstat 시작커밋~1..HEAD` — 변경 통계 (커밋 수·+줄/-줄)
   - 필요 시 CHANGELOG.md [Unreleased], docs/work-log.md 참조
3. **파일 생성**: `docs/weekly-report-YYYYMMDD.md` (날짜 = 보고일, 보통 월요일)

## 형식 (기존 보고서와 동일하게)

```
# 주간보고 (시작일 ~ 종료일)
## DCIM Management System (DC Express) 개발 현황
### 이번 주 요약          ← 커밋 수·코드 변경량·주요 성과 3~4개 볼드
### 계획 대비 진척 (로드맵) ← Phase 표. 지난주 "다음 주 계획" 항목의 이행 여부 반영
### 1~N. 주제별 섹션      ← 성과마다 번호 섹션. 배경→조치→결과 순. 보안/장애는 ⚠️
### 다음 주 계획          ← 우선순위 표
### 이슈/참고사항         ← 운영 주의사항·검증 범위 표
```

## 원칙

- **지난주 계획 대비**를 반드시 짚는다 (이행/이월/변경).
- 검증 상태를 구분해 명시: "verify 통과 = 문법/빌드 검증"이며 **실데이터·현장 동작은 회사망 확인 필요** (CLAUDE.md 검증 루틴).
- 운영에 영향 주는 변경(cron 인증 방식, 배포 절차 등)은 이슈/참고사항 표에 반드시 기재.
- 보고서 작성 후 **붙여넣기용 서술형 3줄 요약**을 채팅으로 함께 제공 (개조식 아닌 문장형).
- 커밋·push까지 완료한다.
