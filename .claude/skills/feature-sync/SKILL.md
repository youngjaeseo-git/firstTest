# features.md 동기화

`docs/features.md`는 구현 현황의 **단일 권위(single source of truth)**다. 구현과 문서를 항상 같은 흐름에서 동기화한다.

## 절차

1. **무엇을 구현했는지 확인**
   - 인자로 받았으면 그 설명 사용
   - 없으면 `git diff HEAD` 또는 `git diff --staged`로 이번 변경을 직접 파악

2. **docs/features.md 읽기**
   - 12개 영역(대시보드/서버 모니터링/인프라 관리/랙/Discovery/Digital Twin/워크로드/알림/설정/운영/용량·리포트/기타)과 "미구현·예정" 섹션 구조 확인
   - 이미 있는 항목이면 **재추가하지 말고 보강만** (CLAUDE.md 중복 방지 원칙)

3. **항목 추가/갱신**
   - 적절한 영역의 표에 한 행 추가: `| 기능 이름 | ✅ 완료 | 1~2줄 설명 (데이터 소스·핵심 동작 포함) |`
   - "미구현·예정"에 있던 기능을 완성했으면 그 행을 해당 영역으로 옮기거나 상태를 ✅로 변경
   - 상태 범례: ✅ 완료 / ⚠️ 부분 / 📋 예정 / 📝 기획

4. **검증**
   - 표 정렬·파이프 개수 확인
   - 같은 커밋에서 구현 코드와 함께 커밋하도록 안내

## 주의

- 기억이 아니라 **실제 코드·git diff**로 무엇이 구현됐는지 확인한다.
- features.md에 없던 영역이면 새 영역을 만들기보다 "기타"에 넣거나 사용자에게 확인한다.
- 한국어로 작성한다.
