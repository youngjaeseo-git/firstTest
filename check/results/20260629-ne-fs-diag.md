## 결론 (확정)

- **두 클러스터 모두 node-exporter는 DaemonSet(monitoring 네임스페이스)으로 운영.** Lab-1도 DaemonSet이 맞다.
- **유일한 차이**: Lab-3 DS에는 호스트 루트 마운트(`hostPath:/` → `mountPath:/host`)와 `--path.rootfs=/host` args가 **빠져 있다**.
- Lab-3는 2026-06-12에 `hostNetwork:true`만 patch됨. 호스트 fs 마운트/args는 적용된 적 없음 → `/etc/*` bind-mount만 노출.
- 둘 다 Helm/Operator 관리가 아님(MGR/OWNER none) → `kubectl patch` 직접 적용 안전(재시작/재배포에도 spec 유지).
- NFS(`/workplace`, `/spot/mlog`)는 Lab-1에서 `mountPropagation:HostToContainer`로 정상 노출됨 → 같은 설정 복제 시 Lab-3도 동일하게 보일 것(실증 기반).

## 해결 방안

Lab-1과 동일한 설정을 Lab-3 DS에 `kubectl patch`로 추가 (이미지는 유지):
- volumes: `rootfs` hostPath `path: /`
- volumeMounts: `rootfs` → `mountPath: /host`, readOnly, `mountPropagation: HostToContainer`
- args 추가: `--path.rootfs=/host --path.procfs=/host/proc --path.sysfs=/host/sys`

적용 스크립트: `check/targetExecCmd/20260629-apply-lab3-rootfs.sh` (Lab-3 마스터 131.100에서 실행)

## 적용 시 주의

1. **이미지 변경 금지** — Lab-3는 로컬 레지스트리 이미지. patch에 image 미포함(strategic merge로 컨테이너 name 매칭, 기존 image 유지).
2. **롤아웃 정체 대비** — NotReady 3대. patch에 `updateStrategy.rollingUpdate.maxUnavailable` 상향 포함. 그래도 정체 시 살아있는 Pod 수동 삭제(DS selector 라벨 사용).
3. 적용은 프로덕션 K8s 변경 → 인프라팀과 공유 권장.
