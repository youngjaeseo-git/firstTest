## 1. 대시보드 (Dashboard)

### 1.1 접속 방법

브라우저에서 DC Express 주소(`http://서버IP:3000`)로 접속하면 대시보드가 기본 화면으로 표시됩니다. 사이드바 메뉴의 **Dashboard** 항목을 클릭해서도 이동할 수 있습니다.

> 📸 [대시보드 전체 화면]

### 1.2 클러스터 필터

대시보드 상단에 **All / Lab-1 / Lab-3** 세 개의 탭 버튼이 있습니다. 탭을 선택하면 해당 클러스터에 속한 장비만 기준으로 모든 카드와 차트가 갱신됩니다.

- **All** — 전체 장비 통합 현황 (기본값)
- **Lab-1** — Lab-1(10.144.38.x 대역) 장비만 표시
- **Lab-3** — Lab-3(10.144.131.x 대역) 장비만 표시

### 1.3 실시간 메트릭 카드

클러스터 필터 아래에 두 줄(4개씩)로 실시간 메트릭 카드가 배치됩니다. 각 카드에는 스파크라인(미니 추세 그래프)이 포함되어 있으며, 30초 간격으로 자동 갱신됩니다.

| 카드 | 표시 내용 | 비고 |
|------|-----------|------|
| **Average CPU** | 전체 서버 평균 CPU 사용률 (%) | 스파크라인 포함 |
| **Average Memory** | 전체 서버 평균 메모리 사용률 (%) | 스파크라인 포함 |
| **Temperature** | CPU 온도 + DIMM 온도 (°C) | 두 값 병렬 표시 |
| **Total Power** | 전체 소비 전력 (W 또는 kW) | 자동 단위 변환 |
| **Nodes** | 정상(UP) / 비정상(DOWN) 노드 수 | 전체 정상 시 초록, 비정상 존재 시 빨강 아이콘 |
| **Average Uptime** | 평균 가동 시간 (일) | |
| **Network In** | 수신 트래픽 (TX 값도 함께 표시) | 스파크라인 포함 |
| **PUE** | 전력 효율 지수 | 아크 게이지 표시, 1.4 미만 Good / 1.4-1.6 Average / 1.6 이상 Poor |

### 1.4 Fleet Top 5

CPU와 Memory 사용률 상위 5개 서버를 막대 그래프로 보여줍니다.

- **Fleet Top 5 — CPU**: 사용률 80% 초과 빨강, 60% 초과 주황, 이하 시안
- **Fleet Top 5 — Memory**: 사용률 80% 초과 빨강, 60% 초과 주황, 이하 초록

각 서버 이름을 클릭하면 해당 서버 상세 페이지로 이동합니다.

### 1.5 서버 상태 및 플랫폼 분포

- **Server Status 도넛 차트** — Active(초록) / Maintenance(주황) / Failed(빨강) 비율을 시각화하며, 중앙에 총 서버 수를 표시합니다.
- **Platform Status** — SPR, GNR-AP, GNR-SP, SRF, Ampere, EMR 등 플랫폼별 가동률과 오프라인 수를 카드 형태로 보여줍니다.

### 1.6 요약 카드

대시보드 하단에 두 개의 요약 카드가 있습니다.

- **Total Equipment** — Active / Maintenance / Failed 장비 수. 각 항목에 마우스를 올리면 해당 장비 목록(최대 10개)이 팝오버로 표시되며, 클릭하면 서버 상세 페이지로 이동합니다.
- **Infrastructure** — 총 랙 수와 룸 수를 표시합니다.

### 1.7 사이드바 (우측)

화면 우측에 두 개의 고정 패널이 있습니다 (xl 이상 해상도에서만 표시).

- **Active Alerts** — 현재 발생 중인 알림 상위 5건. 심각도별 색상(빨강/주황/파랑) 표시. "History" 클릭 시 알림 관리 페이지(`/alerts`)로 이동.
- **Expiring Soon** — 30일 이내 만료 예정 자산. D-day 카운트다운 표시.

### 1.8 Quick Links

대시보드 하단의 Quick Links에서 주요 페이지로 바로 이동할 수 있습니다: **Servers**, **Infrastructure**, **Alerts**, **Discovery**.

## 2. 서버 모니터링 (Server Monitoring)

### 2.1 서버 목록 페이지

사이드바에서 **Servers**를 클릭하거나 `/servers` 주소로 접속합니다.

> 📸 [서버 목록 — 리스트 뷰]

#### 뷰 전환

페이지 우측 상단에 **List / Twin** 토글 버튼이 있습니다.
- **List** — 테이블 형태의 서버 목록 (기본값)
- **Twin** — 데이터센터 평면도 기반 3단계 탐색 뷰 (DataCenter > Room > Rack)

#### 검색 및 필터 (리스트 뷰)

검색창과 4개의 드롭다운 필터를 제공합니다.

- **검색** — hostname, IP, BMC IP, 모델명, 제조사, CPU 정보, Room/Rack 이름으로 통합 검색
- **Model 필터** — 시스템 모델별 필터링
- **Status 필터** — 장비 상태(Active, Maintenance 등)별 필터링
- **Room 필터** — 설치 위치(Room)별 필터링
- **Power 필터** — 전원 상태(Running/Idle/OFF)별 필터링
- **초기화 버튼** — 필터 적용 시 나타나며, 활성 필터 수를 표시합니다

#### 테이블 컬럼 및 정렬

| 컬럼 | 정렬 가능 | 설명 |
|------|:---------:|------|
| Hostname | O | 클릭 시 서버 상세 페이지로 이동 |
| IP | O | Prometheus 인스턴스 IP |
| BMC IP | X | BMC(관리 포트) IP |
| Status | O | 장비 상태 배지 (Active/Maintenance 등) |
| Power | X | 전원 상태 배지 (아래 참조) |
| CPU | X | 제조사 + 모델명 |
| System Model | O | 시스템 모델 배지 |
| Room | X | 설치 Room |
| Rack / U | X | 랙 이름과 U 위치. 미배치 장비는 "미배치"로 표시 |

컬럼 헤더를 클릭하면 오름차순/내림차순 정렬이 전환됩니다.

#### Power State 배지

| 배지 | 색상 | 의미 |
|------|------|------|
| **Running** | 초록 (점 깜빡임) | CPU 사용률 5% 초과 — 워크로드 실행 중 |
| **Idle** | 노랑 | node-exporter 응답 중이나 CPU 사용률 5% 이하 |
| **OFF** | 회색 | node-exporter 무응답 — 서버 꺼짐 또는 네트워크 단절 |

> 💡 Power State는 Prometheus 데이터 기반으로 30초마다 자동 갱신됩니다. 실제 하드웨어 전원 상태와 약간의 지연이 있을 수 있습니다.

#### 트윈 뷰 (Twin View)

트윈 뷰는 물리적 배치를 시각적으로 탐색하는 3단계 드릴다운 구조입니다.

1. **데이터센터 레벨** — SVG 평면도에 Room 배치를 표시. 줌/팬 조작 가능. 온도/가동률/에어플로우 오버레이 지원
2. **Room 레벨** — 선택한 Room 내부의 랙 배치도. 각 랙에 사용률 바와 장비 상태 미니맵 표시
3. **Rack 레벨** — 개별 랙의 U 포지션별 장비 배치. 장비 클릭 시 서버 상세 페이지로 이동

### 2.2 서버 상세 페이지

서버 목록에서 서버를 클릭하면 `/servers/장비ID` 상세 페이지로 이동합니다.

> 📸 [서버 상세 — 메트릭 차트]

#### 상단 정보 요약

서버의 기본 정보를 표시합니다: **IP Address**, **BMC IP**, **Status**(상태 배지 + 전원 표시), **Model**, **Location**(Room/Rack/U), **CPUs**(개수 x 모델 + 아키텍처), **OS**, **Memory**(총 용량 + DIMM 슬롯 현황 + 속도).

BMC IP가 등록된 서버는 **Refresh HW** 버튼(하드웨어 정보 재수집)과 **Power Console**(전원 제어) 카드가 추가로 표시됩니다.

#### 시간 범위 선택

메트릭 차트 상단의 버튼 그룹으로 데이터 조회 범위를 선택합니다.

| 버튼 | 조회 범위 | 데이터 간격 |
|------|-----------|-------------|
| **15m** | 최근 15분 | 15초 |
| **1h** | 최근 1시간 (기본값) | 30초 |
| **6h** | 최근 6시간 | 2분 |
| **24h** | 최근 24시간 | 5분 |
| **7d** | 최근 7일 | 30분 |

#### CPU 섹션

- **CPU Usage** — 전체 CPU 사용률 추이 (%)
- **CPU Load Average** — 1분/5분/15분 로드 평균과 CPU 코어 수 기준선
- **CPU Mode Breakdown** — user/system/iowait/steal 모드별 사용률 분석
- **CFS Throttled** — 컨테이너 CPU 스로틀링 발생량 (sec/s)
- **PCM IPC** — 코어당 명령어 처리량 (Instructions Per Cycle)
- **PCM Cache Hit Rate** — L2/L3 캐시 히트율 (%)
- **Core Heatmap** — 전체 코어를 격자로 표시하며, 사용률에 따라 초록(낮음)에서 빨강(높음)으로 색상 변화. 마우스 오버 시 개별 코어 사용률 확인 가능. 코어별 데이터가 없는 환경에서는 Pod별 CPU 사용량 바 차트로 대체

> 💡 PCM(Performance Counter Monitor) 메트릭은 Intel PCM이 설치된 서버에서만 표시됩니다.

#### Memory 섹션

- **Memory Usage** — 메모리 및 Swap 사용률 추이 (%)
- **Memory Absolute** — Used와 Cache+Buffer의 절대 용량 추이
- **PCM Memory Bandwidth** — DRAM 읽기/쓰기 대역폭

#### Disk 섹션

- **Disk I/O Throughput** — 읽기/쓰기 처리량 (Bytes/s)
- **Disk IOPS** — 초당 I/O 작업 수
- **Disk I/O Latency** — 읽기/쓰기 지연 시간 (ms)
- **Disk Usage** — 디스크 전체 사용률 (%)
- **Filesystem Breakdown** — 마운트 포인트별 사용량 표. 사용률 70% 미만 파랑, 70-90% 노랑, 90% 초과 빨강으로 표시

#### Network 섹션

- **Network Bandwidth** — 수신(RX)/송신(TX) 트래픽 (Bytes/s)
- **Network Errors** — RX/TX 에러 및 드롭 패킷 수
- **TCP Connections** — Established 상태 TCP 연결 수
- **TCP Retransmits** — TCP 재전송 세그먼트 수
- **Network Interface Inventory** — NIC별 상태(UP/DOWN)와 링크 속도(Gbps/Mbps) 목록

#### Hardware 섹션

- **Temperature** — hwmon 센서 온도 + Inlet/Exhaust/CPU Socket 온도 통합 차트 (°C)
- **Power Consumption** — RAPL 기반 전력 소비: Package / DRAM / PP0(Cores) (Watts)
- **Fan Speed** — 팬 회전 속도 (RPM)

> ⚠️ Temperature와 Power 메트릭은 하드웨어 및 IPMI/RAPL 지원 여부에 따라 일부 항목이 표시되지 않을 수 있습니다.

### 2.3 서버 비교 기능

서버 목록 페이지 우측 상단의 **Compare** 버튼을 클릭하면 `/servers/compare` 페이지로 이동합니다.

> 📸 [서버 비교 — 오버레이 차트]

#### 비교 대상 선택

1. 상단 패널에서 검색창을 사용해 서버를 찾습니다 (hostname, IP, Room, Rack으로 검색 가능)
2. 서버 행을 클릭하여 선택합니다 (최대 **4대**)
3. 선택된 서버에는 차트 색상과 동일한 색상 점이 표시됩니다 (파랑, 초록, 주황, 보라 순서)
4. 동일 서버를 다시 클릭하면 선택이 해제됩니다

> 💡 최소 2대 이상 선택해야 차트가 표시됩니다. 4대 선택 시 나머지 서버는 비활성화됩니다.

#### 비교 차트 (6개)

2대 이상 선택하면 6개의 오버레이 차트가 2열 격자로 표시됩니다. 모든 차트는 동일한 시간 범위를 공유하며, 선택한 서버들의 데이터가 하나의 차트에 겹쳐 그려집니다.

| 차트 | 단위 |
|------|------|
| CPU Usage | % (0-100) |
| Memory Usage | % (0-100) |
| Load Average (1m) | 코어 수 |
| Disk I/O (Read) | Bytes/s |
| Network RX | Bytes/s |
| Temperature | °C |

시간 범위 선택기(15m / 1h / 6h / 24h / 7d)는 서버 상세 페이지와 동일하며, 변경 시 6개 차트가 동시에 갱신됩니다.

## 3. 랙 뷰 (Rack View)

랙 뷰 페이지는 데이터센터 내 모든 랙의 물리적 배치와 장비 구성을 한눈에 파악할 수 있는 페이지입니다.

### 3.1 랙 페이지 접속

좌측 사이드바에서 **Racks** 메뉴를 클릭하거나 브라우저에서 `/racks` 경로로 접속합니다.

> 📸 [랙 페이지 메인 화면 — 요약 카드 4개 + Room별 랙 목록]

페이지 상단에는 4개의 요약 카드가 표시됩니다.

- **Total Racks**: 등록된 전체 랙 수
- **Rooms**: 방(Room) 수
- **Equipment**: 랙에 배치된 전체 장비 수
- **U Utilization**: 전체 U 공간 사용률 (사용 중인 U / 전체 U)

### 3.2 Room별 랙 그룹

랙은 소속된 Room 단위로 그룹화되어 표시됩니다. 각 Room 이름 옆에 해당 Room의 랙 수가 배지로 표시됩니다.

각 랙 카드에는 다음 정보가 요약되어 있습니다.

- 랙 이름 및 Row 라벨
- U 사용률 프로그레스 바 (85% 초과: 빨강, 60% 초과: 주황, 이하: 초록)
- 장비 수, 활성(active) 장비 수, 장애(failed) 장비 수
- 최대 전력 용량 (설정된 경우)

### 3.3 Rack Elevation 시각화

랙 카드를 클릭하면 카드가 펼쳐지며 **Rack Elevation** (랙 단면도)이 표시됩니다. 한 번에 하나의 랙만 펼칠 수 있습니다.

> 📸 [랙 카드 펼친 상태 — 좌측 Rack Elevation + 우측 장비 테이블]

펼쳐진 영역은 좌우 2단으로 구성됩니다.

**좌측: 인터랙티브 Rack Elevation**
- U1부터 최상단 U까지 세로로 배열된 슬롯 다이어그램
- 장비가 배치된 슬롯은 **상태별 색상**으로 표시됩니다.
  - ACTIVE: 초록 / MAINTENANCE: 보라 / REPAIR: 주황 / FAILED: 빨강 / PLANNED: 파랑 / INSTALLED: 청록 / DECOMMISSIONED: 회색
- 장비 위에 마우스를 올리면 팝오버로 위치(U), 모델, IP 주소가 표시됩니다.
- 빈 슬롯에는 "empty"라고 표시됩니다.

**우측: 장비 테이블**
- U 위치, Hostname, IP, 상태, 타입, 모델이 테이블로 표시됩니다.
- Hostname 클릭 시 해당 서버 상세 페이지(`/servers/장비ID`)로 이동합니다.
- 각 장비의 U 위치 옆에 위/아래 화살표 버튼으로 장비를 1U씩 이동할 수 있습니다.
- 오른쪽 X 버튼으로 해당 장비를 랙에서 제거(배치 해제)할 수 있습니다.

### 3.4 온도 히트맵 토글

페이지 상단 우측의 **온도 ON/OFF** 버튼을 클릭하면 온도 히트맵 모드가 활성화됩니다.

> 📸 [온도 히트맵 활성화 상태 — 범례 바 + 색상 오버레이된 Rack Elevation]

활성화되면 상단에 온도 범례가 표시됩니다.
- 35도 미만: 하늘색 / 35~45도: 초록 / 45~55도: 노랑 / 55~65도: 주황 / 65~75도: 오렌지 / 75도 이상: 빨강

랙을 펼치면 각 장비 슬롯이 상태 색상 대신 **온도 기반 색상**으로 표시되며, 장비 오른쪽에 온도 수치(도 단위)가 표시됩니다. 온도 데이터는 Prometheus에서 실시간으로 가져옵니다.

### 3.5 장비 드래그앤드롭 배치

Rack Elevation 내에서 장비를 **드래그하여 다른 U 위치로 이동**할 수 있습니다. 장비 좌측의 그립 아이콘을 잡고 원하는 빈 슬롯에 드롭하면 위치가 즉시 변경됩니다. 드롭 가능한 위치에는 "여기에 놓기"라는 파란색 안내가 표시됩니다.

> 💡 U 위치 충돌 방지 기능이 내장되어 있습니다. 이미 장비가 있는 위치나 랙 범위를 초과하는 위치에는 배치할 수 없으며, "해당 위치에 공간이 부족합니다"라는 오류 메시지가 표시됩니다.

**미배치 장비 추가 기능**: Rack Elevation 하단의 **장비 추가** 버튼을 클릭하면 "미배치 장비 추가" 패널이 열립니다. 아직 어떤 랙에도 배치되지 않은 장비 목록이 표시되며, 장비를 선택한 후 U 위치를 지정하고 **배치** 버튼을 누르면 해당 랙에 장비가 추가됩니다. U 위치를 입력하지 않으면 자동으로 첫 번째 빈 슬롯에 배치됩니다.

### 3.6 랙 관리 페이지

랙 페이지 상단의 **관리** 버튼을 클릭하면 랙 관리 페이지(`/racks/manage`)로 이동합니다. 이 페이지는 **관리자(Admin) 또는 운영자(Operator) 권한**이 있어야 접근할 수 있습니다.

> 📸 [랙 관리 페이지 — Room/Rack 관리 탭 + 일괄 배치 탭]

상단에 두 개의 탭이 있습니다.

**Room / Rack 관리 탭**
- Room 생성: 이름, 설명, 정렬 순서(sortOrder)를 입력하여 새 Room을 추가합니다.
- Room 수정/삭제: 기존 Room의 이름, 설명, 정렬 순서를 편집하거나 삭제합니다.
- Rack 생성: 각 Room 아래에 랙을 추가합니다. 이름, Row 라벨, 정렬 순서, 전체 U 수(기본 42U), 최대 전력(W), 평면도 위치(X/Y 좌표)를 지정할 수 있습니다.
- Rack 수정/삭제: 기존 랙의 속성을 편집하거나 삭제합니다.

> ⚠️ 장비가 배치되어 있는 랙은 삭제 전에 장비를 먼저 다른 랙으로 이동하거나 배치 해제해야 합니다.

**일괄 배치 탭**
- 다수의 장비를 한 번에 특정 랙에 배치할 수 있는 기능입니다.

## 4. 디지털 트윈 (Digital Twin)

디지털 트윈 페이지는 데이터센터의 **물리적 구조를 SVG 기반 평면도**로 시각화하여, 방(Room), 랙, 인프라 요소의 실제 배치를 직관적으로 파악할 수 있는 페이지입니다.

### 4.1 디지털 트윈 페이지 접속

좌측 사이드바에서 **Digital Twin** 메뉴를 클릭하거나 `/digital-twin` 경로로 접속합니다. 서버 목록(`/servers`) 페이지의 뷰 전환 버튼으로도 접근할 수 있습니다.

### 4.2 데이터센터 평면도 구성

> 📸 [디지털 트윈 평면도 — Lab-1, Lab-2, Lab-3 방 배치 + 랙/인프라 요소]

평면도는 건물 전체를 1400x650 크기의 SVG 캔버스로 표현합니다.

- **Lab-3** (상단): 보라색 강조, 서버 랙 + 네트워크 스위치, 냉각기, PDU, K8s 마스터 서버 배치
- **Lab-2** (하단 좌측): 녹색 강조, 향후 확장 예정 공간(AVAILABLE SPACE)
- **Lab-1** (하단 우측): 파란색 강조, 서버 랙 + 인프라 요소 배치

각 방에는 다음 정보가 요약 표시됩니다.
- 랙 수, 서버 수, 활성(Active) 서버 수
- U 사용률 프로그레스 바
- 상태 배지 (Healthy 또는 이슈 건수)

방과 방 사이에는 **문(DOOR)** 마커가 표시되어 물리적 동선을 파악할 수 있습니다.

### 4.3 줌/팬 컨트롤

평면도는 자유롭게 확대/축소 및 이동이 가능합니다.

- **마우스 드래그**: 평면도를 팬(이동)합니다. 드래그 중에는 커서가 잡기(grab) 모양으로 변경됩니다.
- **줌 버튼**: 평면도 우측 상단의 버튼을 사용합니다.
  - **+** (확대): 1.2배씩 확대 (최대 4배)
  - **-** (축소): 1.2배씩 축소 (최소 0.5배)
  - **리셋 (사각형 아이콘)**: 원래 크기/위치로 복원

현재 줌 비율은 버튼 좌측에 퍼센트(%)로 표시됩니다.

### 4.4 오버레이 모드

평면도 상단에 3개의 오버레이 토글 버튼이 있습니다. 각 버튼을 클릭하면 해당 오버레이가 활성화/비활성화됩니다.

**온도 (Temp)**
- 랙별 평균 온도를 색상으로 오버레이합니다.
- Prometheus에서 hwmon 온도 데이터를 30초 간격으로 가져와 갱신합니다.
- 색상 단계: 30도 이하 초록 → 45도 라임 → 55도 노랑 → 65도 주황 → 75도 이상 빨강
- 하단에 범례(TEMP)가 표시됩니다.

**용량 (Capacity)**
- 랙별 U 사용률을 색상으로 오버레이합니다.
- 60% 미만: 초록 / 60~85%: 주황 / 85% 초과: 빨강
- 하단에 범례(UTIL)가 표시됩니다.

**에어플로우 (Airflow)**
- 각 방 내부에 냉기 흐름 방향을 화살표로 표시합니다.
- 방 하단에 "COLD → HOT" 라벨이 표시되어 냉기/열기 흐름을 안내합니다.
- 개별 냉각기(AC) 요소에서도 설정된 방향으로 에어플로우 화살표가 표시됩니다.

> 💡 오버레이 모드는 한 번에 하나만 활성화됩니다. 같은 버튼을 다시 클릭하면 오버레이가 해제됩니다.

### 4.5 랙 호버 팝오버

평면도 위의 랙에 마우스를 올리면 상세 정보 **팝오버**가 표시됩니다.

> 📸 [랙 호버 팝오버 — 서버 수, U 사용률, 온도, 서버 목록]

팝오버에는 다음 정보가 포함됩니다.
- **랙 이름** 및 "클릭하여 이동" 안내
- **서버 수**: 활성 서버 / 전체 서버 (장애 서버가 있으면 빨간색 배지로 표시)
- **U 사용률**: 퍼센트 + 사용 U/전체 U + 프로그레스 바
- **평균 온도**: 온도 데이터가 있는 경우 표시 (색상으로 구간 표시)
- **서버 호스트명 목록**: 최대 6개까지 표시, 초과 시 "+N" 배지

**랙 클릭 시**: 랙 상세 페이지(`/racks?highlight=랙ID`)로 이동하며, 해당 랙이 자동으로 펼쳐지고 화면이 해당 위치로 스크롤됩니다.

### 4.6 편집 모드 (관리자용)

평면도 상단의 **편집(연필 아이콘)** 버튼을 클릭하면 편집 모드가 활성화됩니다. 편집 모드에서는 평면도 테두리가 청록색 점선으로 변경되고, 팬(드래그 이동)이 비활성화됩니다.

> 📸 [편집 모드 활성화 상태 — 점선 테두리 + 요소별 편집 핸들]

하단에 조작 안내가 표시됩니다: `L-click: Select / L-drag: Resize / R-drag: Move / R-tap: Menu / +: Add / x: Delete`

**랙/요소 크기 조절 (좌클릭 드래그)**
- 랙이나 인프라 요소를 좌클릭한 상태로 드래그하면 크기(width/height)가 조절됩니다.
- 우하단 모서리의 리사이즈 핸들을 드래그할 수도 있습니다.
- 크기 조절 중에는 현재 크기(W x H)가 표시됩니다.

**랙/요소 이동 (우클릭 드래그)**
- 랙이나 인프라 요소를 우클릭한 상태로 드래그하면 위치가 이동됩니다.
- 이동 범위는 소속된 방(Room) 경계 내로 제한됩니다.
- 변경된 위치는 API를 통해 즉시 서버에 저장됩니다.

**인프라 요소 추가 (+버튼)**
- 각 방의 우상단에 **+** 버튼이 표시됩니다.
- 클릭하면 추가 가능한 요소 메뉴가 나타납니다: COOLING, PDU, SWITCH, MASTER SERVER, DOOR
- 원하는 타입을 선택하면 해당 방에 기본 크기/위치로 요소가 추가됩니다.

**인프라 요소 삭제 (x버튼)**
- 각 요소 우상단에 빨간색 **x** 버튼이 표시됩니다.
- 클릭하면 해당 요소가 즉시 삭제됩니다.

**크기 통일 (우클릭 메뉴)**
- 편집 모드에서 랙이나 요소를 우클릭(탭)하면 컨텍스트 메뉴가 표시됩니다.
- **"이 크기로 통일"**: 같은 방 내 동일 타입의 모든 요소에 현재 요소의 크기를 일괄 적용합니다.
- 냉각기(COOLING)에는 추가로 **"방향 전환"** 메뉴가 표시되어 에어플로우 방향(상/우/하/좌)을 순환 전환할 수 있습니다.
- 문(DOOR)에도 **"방향 전환"** 메뉴가 있어 가로/세로 방향을 전환합니다.

**다중 선택 정렬**
- 좌클릭으로 여러 랙/요소를 선택할 수 있습니다 (선택된 항목은 파란색 테두리로 강조).
- 2개 이상 선택하면 상단 툴바에 정렬 버튼이 나타납니다.
  - **가로 정렬**: 선택된 항목들의 Y 좌표를 평균값으로 통일합니다.
  - **세로 정렬**: 선택된 항목들의 X 좌표를 평균값으로 통일합니다.
- 선택 항목 수가 버튼 옆에 표시됩니다. 빈 영역을 클릭하면 선택이 해제됩니다.

**방(Room) 이동/크기 조절**
- 방 영역을 우클릭 드래그하면 방 전체의 위치를 이동할 수 있습니다.
- 방 우하단의 핸들을 좌클릭 드래그하면 방의 크기를 조절할 수 있습니다 (최소 100x80).
- 변경된 방의 좌표와 크기(layoutX/Y/W/H)는 API를 통해 즉시 저장됩니다.

> ⚠️ 편집 모드에서는 랙 클릭 이동과 랙 호버 팝오버가 비활성화됩니다. 편집이 끝나면 반드시 **완료(체크 아이콘)** 버튼을 클릭하여 편집 모드를 종료하세요.

## 5. BMC/Redfish 제어

### 5.1 BMC란?

BMC(Baseboard Management Controller)는 서버 메인보드에 내장된 독립 관리 프로세서입니다. 서버의 OS와 별개로 동작하며, 서버가 꺼진 상태에서도 전원 제어, 하드웨어 센서 읽기, 원격 콘솔 접속 등을 수행할 수 있습니다.

DC Express는 Redfish 표준 API를 통해 BMC와 통신합니다. Redfish는 DMTF에서 정의한 RESTful 서버 관리 표준으로, 제조사(Intel, Dell, HPE, Supermicro 등)와 관계없이 동일한 방식으로 서버를 제어합니다.

---

### 5.2 BMC IP 설정

BMC 기능을 사용하려면 장비에 BMC IP 주소가 등록되어 있어야 합니다. 세 가지 방법으로 설정할 수 있습니다.

**방법 1: 장비 등록/수정 시 직접 입력**

장비 등록(`/infrastructure/new`) 또는 수정(`/infrastructure/장비ID/edit`) 화면에서 **BMC IP** 필드에 IP 주소를 입력합니다.

> 📸 장비 수정 페이지의 BMC IP 입력 필드

**방법 2: BMC 관리 페이지에서 인라인 편집**

`설정 > BMC 관리`(`/settings/bmc`) 페이지의 **BMC IP 매핑** 탭에서 장비 목록의 연필 아이콘을 클릭하면 해당 행에서 바로 BMC IP를 편집할 수 있습니다. Enter로 저장, Esc로 취소합니다.

필터 버튼으로 **전체 / BMC 설정됨 / BMC 미설정** 장비만 표시할 수 있습니다.

> 📸 BMC IP 매핑 탭 - 인라인 편집 모드

**방법 3: 자동 유도 (일괄 자동 설정)**

BMC IP가 미설정이고 Host IP가 있는 서버들에 대해, Host IP의 마지막 옥텟을 이용하여 `192.168.10.{마지막옥텟}` 형식으로 자동 생성합니다. **미설정 서버 자동 설정** 버튼을 클릭하면 대상 수를 확인하는 다이얼로그가 표시되며, 확인 시 일괄 적용됩니다.

> 💡 자동 유도 규칙은 BMC 네트워크가 `192.168.10.x` 대역인 환경에 맞춰져 있습니다. 다른 대역을 사용하는 경우 수동 설정이 필요합니다.

---

### 5.3 BMC 자격증명 관리

BMC 접속에 필요한 사용자명과 비밀번호는 환경 변수로 관리됩니다.

**기본 자격증명 설정**

`.env` 파일에 다음 두 변수를 설정합니다:

```
BMC_USERNAME=admin
BMC_PASSWORD=비밀번호
```

이 자격증명은 모든 서버의 BMC 접속에 공통으로 사용됩니다. 설정되지 않으면 전원 제어, 센서 조회, HW 갱신 기능이 모두 비활성화되며 "BMC credentials not configured" 메시지가 표시됩니다.

**BMC 프록시 설정 (원격 사이트)**

Lab-3 등 네트워크가 분리된 원격 사이트의 BMC에 접근하려면 Room 설정에서 **BMC 프록시 URL**을 지정합니다. 프록시가 설정된 Room에 배치된 장비는 직접 BMC에 접근하는 대신 프록시 서버를 경유합니다.

> 💡 프록시 URL 예시: `http://10.144.131.100:8443`. Room(방) 단위로 설정되므로, 같은 방에 있는 모든 장비에 자동 적용됩니다.

---

### 5.4 BMC 센서 모니터링

서버 상세 페이지(`/servers/장비ID`)에서 BMC IP가 설정된 장비는 **BMC Sensors (Thermal & Power)** 카드가 표시됩니다.

> 📸 BMC Sensors 카드 - 전력/온도/팬 센서 표시

표시되는 센서 정보:

| 구분 | 내용 | 표시 방식 |
|------|------|----------|
| **전력 소비** | 현재 소비 전력(W), 전체 용량 대비 비율 | 숫자 + 프로그레스바 |
| **전원 공급 장치(PSU)** | PSU별 이름, 모델, 용량(W), 상태 | 카드 그리드 |
| **온도** | 센서별 현재 온도(°C), 임계값 대비 바 | 바 차트 (녹/황/적) |
| **팬** | 팬별 회전 속도(RPM) | 숫자 그리드 |

온도 센서는 임계값(Critical) 대비 85% 이상이면 황색, 임계값 이상이면 적색으로 표시됩니다.

우측 상단의 **Refresh** 버튼을 클릭하면 BMC에서 최신 센서 데이터를 다시 가져옵니다. 마지막 조회 시각이 함께 표시됩니다.

### 5.5 전원 제어 (Power Control)

서버 상세 페이지의 **Power & Console** 카드에서 서버의 전원 상태를 확인하고 제어할 수 있습니다. 현재 전원 상태(On/Off/Unknown)가 아이콘과 함께 표시되며, 상태 새로고침 버튼(회전 아이콘)으로 갱신할 수 있습니다.

> 📸 Power & Console 카드 - 전원 상태 및 제어 버튼

**전원 제어 액션 목록:**

| 버튼 | Redfish ResetType | 설명 | 위험도 |
|------|------------------|------|--------|
| Graceful Restart | `GracefulRestart` | OS에 정상 재부팅을 요청합니다. 가장 안전한 옵션입니다. | 보통 |
| Force Restart | `ForceRestart` | BMC를 통해 강제 재시작합니다. 저장되지 않은 데이터가 유실될 수 있습니다. | 주의 |
| Graceful Shutdown | `GracefulShutdown` | OS에 정상 종료를 요청합니다. | 주의 |
| Force Off | `ForceOff` | 전원을 즉시 차단합니다. 서버가 응답하지 않을 때만 사용하세요. | 위험 |
| Power On | `On` | 시스템 전원을 켭니다. | 보통 |

> ⚠️ **Force Off**는 물리적으로 전원 코드를 뽑는 것과 동일합니다. 운영 중인 서버에 사용하면 파일시스템 손상, 데이터 유실이 발생할 수 있습니다. 반드시 서버가 응답하지 않는 상황에서만 사용하세요.

**확인 절차:**
전원 제어 버튼을 클릭하면 확인 다이얼로그가 표시됩니다. 안전을 위해 다음 정보를 입력해야 합니다:
1. **호스트명 입력**: 서버 호스트명을 정확히 타이핑 (실수 방지)
2. **사유 입력** (필수): 최소 3자 이상의 사유
3. **티켓 참조** (선택): 관련 작업 티켓 번호

> 💡 전원 제어는 **ADMIN** 또는 **OPERATOR** 역할이 필요합니다. VIEWER 역할은 전원 상태 조회만 가능하며 제어 버튼이 비활성화됩니다. 모든 전원 제어 이력은 감사 로그에 자동 기록됩니다.

**일괄 전원 제어**

`설정 > BMC 관리`(`/settings/bmc`) 페이지의 **일괄 작업** 탭에서 여러 서버를 선택하여 한 번에 전원 제어를 수행할 수 있습니다. 체크박스로 대상 서버를 선택한 후 **Power Control** 버튼을 클릭하면 전원 제어 패널이 열립니다. 사유를 입력하고 원하는 액션 버튼을 클릭합니다.

> ⚠️ 일괄 전원 제어는 선택된 모든 서버에 동시에 명령을 보냅니다. 실행 전 대상 서버 목록을 반드시 확인하세요.

### 5.6 BMC 웹 콘솔 접속

서버 상세 페이지의 요약 정보 바에 BMC IP가 표시됩니다. BMC 웹 관리 콘솔에 접속하려면 브라우저에서 `https://BMC_IP` 형식으로 직접 접속합니다.

> 💡 BMC는 대부분 자체 서명 인증서를 사용하므로, 브라우저에서 보안 경고가 표시될 수 있습니다. 내부 네트워크에서는 "고급 > 계속 진행"으로 접속하면 됩니다.

### 5.7 하드웨어 자동 수집 (Refresh HW)

Redfish API를 통해 서버의 하드웨어 정보를 BMC에서 자동으로 가져와 DB에 저장합니다.

**사용 방법:**
서버 상세 페이지(`/servers/장비ID`) 또는 자산 관리 페이지(`/infrastructure/장비ID`) 상단의 **Refresh HW** 버튼을 클릭합니다. BMC IP가 설정된 장비에서만 이 버튼이 표시됩니다.

> 📸 서버 상세 페이지 상단의 Refresh HW 버튼

**수집되는 정보:**

| 항목 | 수집 내용 |
|------|----------|
| **시스템 기본 정보** | 제조사, 모델명, 시리얼번호, BIOS 버전 |
| **CPU** | 소켓별 제조사, 모델, 코어 수, 스레드 수, 최대 클럭, TDP, 아키텍처 |
| **메모리 (DIMM)** | 슬롯별 장착 여부, 용량(GB), 타입(DDR4/DDR5 등), 제조사, 파트넘버, 시리얼, 속도, 랭크, ECC 여부 |
| **네트워크 인터페이스** | 포트명, MAC 주소, 링크 속도, 연결 상태, IPv4 주소 |

수집 완료 시 토스트 메시지로 결과가 표시되며 (예: "Intel M50CYP — 2 CPUs, 256 GB, 16/32 DIMMs, 4 NICs"), 페이지가 자동 새로고침됩니다.

**일괄 HW 갱신**

`설정 > BMC 관리` 페이지의 **일괄 작업** 탭에서 여러 서버를 선택하고 **Refresh HW** 버튼을 클릭하면 일괄 수집이 가능합니다. 결과 패널에서 서버별 성공/실패 상태와 수집된 정보 요약을 확인할 수 있습니다.

> 💡 신규 서버를 대량 등록한 후 BMC IP를 설정하고 일괄 HW 갱신을 실행하면, 수동 입력 없이 모든 하드웨어 정보를 자동으로 채울 수 있습니다.

## 6. 쿠버네티스(K8s) 연동

DC Express는 Prometheus를 통해 쿠버네티스 클러스터의 노드와 파드(Pod) 정보를 실시간으로 수집하여 표시합니다. 별도의 K8s API 직접 연결 없이, 이미 구축된 Prometheus 인프라를 활용합니다.

### 6.1 메트릭 수집 구조

K8s 관련 데이터는 Prometheus에 등록된 세 가지 수집원(exporter)에서 옵니다.

```
[K8s 클러스터]
  |
  |-- kube-state-metrics (1대)    --> 노드/파드 상태 정보 (kube_pod_info, kube_node_info 등)
  |-- kubernetes-cadvisor (24대)  --> 컨테이너별 CPU/메모리/디스크/네트워크 사용량
  |-- kubelet (각 노드)           --> 파드 실행 수 (kubelet_running_pods)
  |
  v
[Prometheus] ---> [DC Express API] ---> [웹 UI]
```

| 수집원 | 역할 | instance 형식 | 주요 메트릭 |
|--------|------|---------------|-------------|
| kube-state-metrics | 노드/파드 상태, 용량 정보 | hostname | kube_pod_info, kube_node_status_capacity, kube_pod_status_phase |
| kubernetes-cadvisor | 컨테이너 리소스 사용량 | hostname | container_cpu_usage_seconds_total, container_memory_working_set_bytes |
| kubelet | 파드 실행 현황 | IP:port | kubelet_running_pods |

> 💡 **K8s 용어 안내**: "파드(Pod)"는 쿠버네티스에서 실행되는 컨테이너 묶음의 최소 단위입니다. "네임스페이스(Namespace)"는 파드를 논리적으로 그룹화하는 이름 공간입니다. "노드(Node)"는 파드가 실행되는 물리 서버입니다.

### 6.2 Prometheus Discovery (설정 > 타겟 관리)

사이드바 하단 **Settings > Prometheus Discovery** 메뉴에서 접근합니다. Prometheus에 등록된 모든 스크래핑 타겟을 조회하고, DC Express 장비로 연결할 수 있습니다.

**타겟 동기화**

1. 페이지 상단 **"동기화 실행"** 버튼을 클릭합니다.
2. Prometheus `/api/v1/targets` API를 호출하여 모든 타겟을 자동 수집합니다.
3. 동기화 결과로 전체 동기화 수, 신규 타겟 수, 업데이트 수가 표시됩니다.

> 📸 *동기화 완료 후 결과 카드 (전체 동기화 / 신규 / 업데이트 건수)*

**타겟 필터 및 검색**

타겟 목록 위 필터 영역에서 다음 조건을 조합하여 검색할 수 있습니다:

- **Job**: node-exporter, kubernetes-cadvisor, kube-state-metrics 등 Job별 필터
- **Health**: UP / DOWN 상태 필터
- **등록 여부**: 장비 연결됨(Linked) / 미연결(Unlinked) 필터
- **텍스트 검색**: instance 주소 또는 hostname으로 검색
- 50개 단위 페이지네이션 적용

**장비 등록/해제**

- 미연결 타겟의 **"등록"** 버튼을 클릭하면 해당 타겟의 정보(hostname, IP)로 장비가 자동 생성되고 연결됩니다.
- 이미 연결된 타겟은 **"해제"** 버튼으로 연결을 끊을 수 있습니다 (확인 다이얼로그 표시).

> ⚠️ 등록 시 CPU 코어 수와 메모리 용량이 Prometheus 메트릭에서 자동 감지됩니다. 감지가 불가능한 경우 수동으로 수정해야 합니다.

### 6.3 서버 상세 페이지의 K8s 정보

개별 서버 상세 페이지(`/servers/서버ID`)에는 **Node Resources** 카드가 표시됩니다. 이 카드는 kube-state-metrics 데이터를 기반으로 해당 서버(노드)의 리소스 현황을 보여줍니다.

**게이지 정보 (4개 항목)**

| 항목 | 설명 | 소스 메트릭 |
|------|------|-------------|
| CPU | 현재 Load Average / 전체 코어 수 | load5, kube_node_status_capacity |
| Memory | 사용 중 / 전체 메모리 | memoryUsedBytes, kube_node_status_capacity |
| Disk | 사용 중 / 전체 디스크 | hostDiskUsedBytes, kube_node_status_capacity |
| Pods | 실행 중인 파드 수 | kubelet_running_pods |

각 항목에는 사용률 프로그레스 바가 표시되며, 70% 이상은 노란색, 90% 이상은 빨간색으로 경고합니다.

**Running Pods 목록**

게이지 아래에 해당 노드에서 실행 중인 모든 파드 목록이 `namespace/pod이름` 형식으로 표시됩니다. kube_pod_info 메트릭에서 해당 노드에 할당된 파드를 조회합니다.

> 📸 *서버 상세 페이지의 Node Resources 카드 — CPU/Memory/Disk 게이지와 Running Pods 목록*

## 7. 워크로드 관리 (Workload Management)

사이드바 **Workloads** 메뉴를 클릭하면 워크로드 관리 페이지(`/workloads`)로 이동합니다. 이 페이지는 K8s 네임스페이스 단위로 실행 중인 평가 워크로드를 모니터링하고, 과거 이력을 달력 형태로 관리합니다.

> 💡 DC Express에서 "워크로드"는 특정 네임스페이스에서 실행되는 파드 그룹을 의미합니다. 시스템 네임스페이스(kube-system, monitoring, calico-system 등)는 자동으로 제외됩니다.

### 7.1 Active 탭

페이지 접속 시 기본으로 표시되는 탭입니다. Prometheus에서 실시간으로 파드 상태를 조회하여 표시합니다.

**네임스페이스별 카드**

각 네임스페이스가 하나의 카드로 표시되며, 다음 정보를 포함합니다:
- **Health 상태 표시등**: 네임스페이스 내 가장 심각한 파드 상태에 따라 색상이 결정됩니다.
- **파드 수 / 노드 수**: 해당 네임스페이스의 파드와 노드 개수
- **시작일 / 경과 시간**: 가장 오래된 파드의 생성일과 경과 시간

| Health 상태 | 색상 | 의미 |
|-------------|------|------|
| Running | 녹색 | 모든 파드 정상 실행 중 |
| Pending | 노란색 | 파드 대기 중 (스케줄링 또는 이미지 다운로드) |
| Warning | 주황색 | ImagePullBackOff 등 경고 상태 |
| Error | 빨간색 | CrashLoopBackOff 등 오류 발생 |
| Completed | 회색 | 파드 실행 완료 (Succeeded) |

> 📸 *Active 탭 — 네임스페이스별 워크로드 카드 (Health 색상별 구분)*

카드를 클릭하면 해당 네임스페이스의 상세 페이지(`/workloads/네임스페이스명`)로 이동합니다. 상세 페이지에서는 개별 파드 목록, 평가 프로젝트 관리(생성/삭제), 테스트 결과, 태스크, 메모를 확인할 수 있습니다.

**종료된 워크로드**

Active 탭 하단에는 **"종료된 워크로드"** 섹션이 표시됩니다. DB에 기록된 과거 평가 프로젝트 중 현재 Prometheus에서 파드가 감지되지 않는 네임스페이스를 보여줍니다. 클릭하면 해당 네임스페이스의 상세 페이지에서 과거 평가 기록(results, tasks, notes)을 확인할 수 있습니다.

### 7.2 History 탭

달력 타임라인 형태로 모든 워크로드 이력을 시각화합니다.

**네임스페이스 필터**

달력 위 필터 영역에서 체크박스로 특정 네임스페이스만 선택하여 표시할 수 있습니다. **ALL** 체크박스로 전체 선택/해제가 가능하며, 현재 실행 중인 네임스페이스에는 **(LIVE)** 표시가 붙습니다. 각 네임스페이스는 고유 색상으로 구분됩니다.

**달력 뷰**

- 월 단위 달력에 프로젝트 기간이 색상 바로 표시됩니다.
- **좌/우 화살표**로 월 이동, **Today** 버튼으로 현재 월로 복귀합니다.
- 날짜를 클릭하면 해당 날짜에 진행 중이던 프로젝트 목록이 달력 아래에 표시됩니다.
- 바를 클릭하면 프로젝트 상세 팝업이 열립니다.

> 📸 *History 탭 — 달력 타임라인 뷰 (색상 바로 프로젝트 기간 표시)*

**프로젝트 상세 팝업**

달력의 바를 클릭하면 팝업 창이 열리며 다음 정보를 확인할 수 있습니다:
- **Overview**: 기간(일수), 파드 수, 테스트 수, 태스크 수
- **Pods**: 현재 실행 중인 파드 목록과 Health 상태
- **Phases**: 평가 단계별 상태 (PASSED/FAILED/IN_PROGRESS)
- **Test Results**: 워크로드별 테스트 결과 테이블 (PASS/FAIL, 서버, 사이클, 값)
- **Tasks/Notes**: 관련 태스크와 메모

**전체 워크로드 목록**

달력 아래에 모든 워크로드가 리스트 형태로 표시됩니다. 각 항목에는 상태 아이콘(IN_PROGRESS, COMPLETED, CANCELLED, ON_HOLD, PLANNED), 네임스페이스명, 기간, 결과/태스크 수가 표시됩니다. 완료/취소된 프로젝트는 호버 시 삭제 버튼이 나타납니다.

> ⚠️ 프로젝트 삭제 시 관련 결과(results), 태스크(tasks), 메모(notes)가 모두 삭제됩니다. 삭제 전 확인 다이얼로그가 표시됩니다.

### 7.3 대시보드 연동

메인 대시보드(`/`)에는 **Active Workloads** 카드가 있으며, 워크로드 페이지와 동일한 실시간 데이터를 요약 형태로 보여줍니다.

- 네임스페이스별 Health 상태, 파드/노드 수, 시작일, 경과 시간 표시
- Warning 파드가 있으면 해당 사유(예: CrashLoopBackOff)와 파드명 표시
- 노드 온도 바: 각 노드의 현재 온도를 프로그레스 바로 표시 (50도 미만 녹색, 65도 이상 주황, 80도 이상 빨간색)
- 대시보드 상단 클러스터 필터(**All / Lab-1 / Lab-3**)에 따라 해당 클러스터의 워크로드만 필터링되어 표시됩니다.
- 카드 클릭 시 `/workloads/네임스페이스명` 상세 페이지로 이동합니다.
- 30초 간격으로 자동 갱신됩니다.
