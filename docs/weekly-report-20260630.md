### 1. 파일시스템 현황 — Lab-3 호스트 파일시스템 노출 완성

- **증상**: 서버 상세 "파일시스템 현황"이 일부 서버만 정상, Lab-3는 `/etc/*` bind-mount만 표시
- **원인**: Lab-3 node-exporter DaemonSet에 호스트 루트 마운트(`hostPath:/`)·`--path.rootfs`가 누락 (Lab-1만 적용돼 있었음). cAdvisor는 mountpoint 라벨이 없어 폴백 시 깨짐
- **조치**: Lab-3 node-exporter에 Lab-1과 동일 설정 패치 → **NFS(/workplace, /spot/mlog) 포함 실제 마운트 노출 확인**. 파일시스템 테이블은 node-exporter 전용으로 정리
- Data-First 진단 스크립트(전체 서버 fs 유무, cAdvisor 라벨 등)로 추측 없이 수정

### 2. 대시보드 "파일시스템 경고" 위젯 수정

- 호스트명 표시(IP+hostname→id 맵), 깨진 링크(`/servers/{id}`) 수정
- **중복 표시 제거**: 같은 서버가 여러 job(node-exporter/kubernetes-pods/server-info)으로 중복 수집되던 것을 **서버 단위 dedup**으로 1줄 표시
- 회귀 수정: job 필터가 과해 실제 위험 서버(85% 디스크)를 숨기던 버그 발견·수정

### 3. 알림 규칙 평가 엔진 가동 (Phase 4)

- `/api/cron/alert-check` — 5분 주기로 규칙 평가 → 임계 초과 시 알림 생성, 해소 시 자동 RESOLVED
- ACKNOWLEDGED 알림 중복 생성·미해소 수정, Prometheus 빈응답 시 잘못된 일괄 해소(플랩) 방지
- 알림 이력 날짜 필터를 **서버 사이드**로 전환 (총계·페이지네이션 정합)
- crontab 등록(CRON_SECRET 인증) 정비

### 4. 운영 DB 장애 긴급 복구 ⚠️ (데이터 무손실)

- **배경**: 알림 cron을 docker-compose로 적용하려다, 운영이 "**앱=systemd / DB=docker(포트 5433)**" 하이브리드 구조임을 인지하지 못해 `docker compose up`이 운영 도커 DB를 잘못 재생성 → DB 다운
- **대응**: 8-에이전트로 실제 배포 구조 규명 → 데이터 볼륨(`firsttest_pgdata`) 보존 확인 → DB를 5433으로 안전 재기동 → **테이블 30·장비 30 전부 복구(데이터 손실 0)**
- **재발 방지**: 실제 배포 구조를 README·project-handover §3-1에 명문화(금지사항 포함), docker용 cron 스크립트에 경고 표시, 읽기전용 진단 스크립트 다수 작성
- **교훈**: 외부/인프라 구조는 추측 금지, Data-First로 먼저 확인
