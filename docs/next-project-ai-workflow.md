## 1. 훅(Hooks) — 규칙을 "말"에서 "강제"로 ★최우선

CLAUDE.md 규칙은 AI가 읽고 지키길 *기대*하는 방식이다. AI의 준수율은 100%가 아니지만 **훅은 100%**다.

### 1-1. PreToolUse 훅 — 위험 명령 차단
- 명령이 실행되기 **전에** 스크립트가 패턴을 검사해 거부(exit code 2 = 차단).
- **근거 사례**: 2026-06-29 DB 사고 — `docker compose up -d app` 한 줄이 운영 DB(5433)를 내렸다. CLAUDE.md에 "금지"라고 적어뒀지만 말로는 못 막았다. 훅이었으면 원천 차단.
- 차단 목록 예: `docker compose up.*app`, `docker compose down`, `prisma migrate reset`, `rm -rf`, 운영 포트 대상 명령.

### 1-2. Stop 훅 — 검증 강제
- AI가 턴을 마칠 때 자동으로 `npm run verify` 실행, 실패하면 "고치고 다시 끝내라"고 AI에게 피드백.
- "검증을 잊는 것"이 구조적으로 불가능해진다.

### 1-3. PostToolUse 훅 — 자동 포맷
- 파일 수정 직후 prettier 자동 실행. 스타일 지적 왕복 제거.

**설정 위치**: `.claude/settings.json`의 `hooks` 항목. 첫 주 반나절 투자로 충분.

## 2. 검증 루프 — "tsc 통과 → 런타임 에러" 종결 ★고통 1위였음

### 2-1. 브라우저 실검증 (Playwright)
- 기능 구현 후 "서버 띄우고 → 해당 페이지를 실제로 열고 → 콘솔 에러/스크린샷 확인"까지를 AI에게 시킨다.
- **근거 사례**: capacity/reports 크래시(RSC 아이콘 함수 직렬화) — tsc·lint·테스트 전부 통과했지만 화면은 통째로 죽어 있었다. 브라우저 검증 루프였으면 push 전에 잡혔다.
- Claude Code 환경에 Chromium+Playwright가 기본 설치돼 있고, `/verify`·`/run` 스킬이 이 용도다.

### 2-2. 테스트 동봉 규칙 (TDD 루프)
- "기능 커밋 = 코드 + 테스트 + features.md"를 규칙(가능하면 훅)으로.
- "테스트 먼저 작성 → 실패 확인 → 통과까지 구현 반복"을 명시적으로 지시하는 방식도 유효.
- **근거 사례**: 1차 마감 시점 라우트 74개 중 테스트 1개(1.4%). S1/S2 권한 우회도 이 공백에서 나왔다(`test-summary.md`). AI에게 테스트 작성의 한계비용은 매우 낮은데 쌓아두지 않았다.

## 3. 에이전트 — 쓰던 패턴의 확장

### 3-1. 내장 스킬 습관화
- **`/code-review`**: 머지 전 버그 탐색 + 적대적 검증. 8-에이전트 감사를 손으로 지시했던 것의 스킬판. **큰 기능 머지 전 필수 습관**으로.
- **`/security-review`**: 인증·권한 코드 변경 시.
- **`/simplify`**: 리팩터링 후보 정리(이번 프로젝트 refactor 3/576건의 해독제).

### 3-2. 플랜 모드 선행 (탐색 → 계획 → 승인 → 구현)
- 큰 작업은 바로 구현하지 않고 플랜 모드(Shift+Tab)로 시작: 관련 코드 탐색 → 계획 제시 → 사람이 승인 → 구현.
- **근거 사례**: 회고 Improve 1번 "초기 기획 부족 → Phase 4 대량 수정". 계획 승인 단계가 있었으면 만들고-부수고 비용이 줄었다.

### 3-3. git worktree 병렬 세션
- 독립적인 기능 2~3개를 각각 worktree + 별도 Claude 세션으로 동시 진행. 1인 개발의 체감 속도 배가.
- 주의: 같은 파일을 건드리는 작업은 병렬화하지 않는다(충돌).

## 4. MCP — 폐쇄망 제약을 감안한 선별

MCP(Model Context Protocol)는 AI에게 외부 시스템 접근을 달아주는 표준 커넥터. **개발 환경과 폐쇄망을 구분**해서 판단한다.

### 개발 환경(클라우드 세션)에서 유용
| MCP | 효과 |
|-----|------|
| GitHub MCP | PR·이슈·CI 조작 (이번 프로젝트에서 이미 사용 중) |
| **PostgreSQL MCP** | 개발 DB 스키마·데이터를 AI가 직접 조회 — "확인 스크립트 작성 → 사용자 실행 → 수동 타이핑" 루프가 **개발 DB에 한해** 사라짐 |
| Playwright MCP | 브라우저 조작·스크린샷 (§2-1과 결합) |

### 폐쇄망에서는
- MCP가 닿지 않으므로 **현행 Data-First 방식(스크립트 + 수동 타이핑 + `check/results/` 영구 저장)이 계속 정답**.
- 단, 다음 프로젝트에서 사내망에 Claude Code를 직접 설치할 수 있다면(폐쇄망용 프록시/게이트웨이 구성 사례 있음) Prometheus·K8s MCP 연결이 게임 체인저 — 실데이터 확인 78+ fix의 고통 대부분이 사라진다. **1차 마감 후 보안팀과 타진해볼 가치가 있는 항목.**
